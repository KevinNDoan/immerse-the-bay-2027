## Half-done: relay review findings, not yet fixed

All in `relay/zap_relay/`. Checked against https://docs.reactor.inc/model-api-reference/visko-orbis-stable/schema.md and the installed SDK source.

1. `sources.py`, `set_resolution`: the payload is wrong. The command takes `{"resolution": "<tier>"}` where the tier is one of `1080p`, `2k`, `4k` from the session's `available_resolutions`. Remove the call, or send it only when a new `ORBIS_RESOLUTION` setting is non-empty.
2. `sources.py`, `set_audio_enabled`: the key is `audio_enabled`, not `enabled`. Sound is on by default, so remove the call.
3. `app.py`, `World.steer`: every steer is appended to the prompt forever. Replace with three slots: scene (the opening prompt), camera (the latest `move` or `look`, replaced each time), event (the latest `event` or `voice`, replaced each time). Compose one prompt from them and end it with "a single unbroken take", which Reactor's prompt guide recommends.
4. `sources.py`, live frame size: Orbis delivers at 1080p or larger, not 832x480. Downscale frames wider than a `RELAY_MAX_WIDTH` setting (suggest 1280) before JPEG encoding, and change `docs/protocol.md` to say clients must not assume a frame size in live mode.
5. `sources.py`, `_receive_video`: accept a 4-dimensional array as a batch of frames, as the schema describes `(N, H, W, 3)`. The SDK docstring says `(height, width, 3)`, so handle both.
6. `sources.py`: register `reactor.on_message` and surface `command_error` and `generation_complete` as status or error messages. After `generation_complete`, the session is waiting and needs `start` again.

The correct command shapes: `set_prompt {"prompt": str}`, `set_image {"image": FileRef}` after `upload_file`, `start {}`, `pause {}`, `resume {}`, `reset {}`. Order for a starting image: upload, `set_image`, `set_prompt`, `start`.
